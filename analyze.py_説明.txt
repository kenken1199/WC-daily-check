===================================================================
analyze.py 解説
===================================================================

このファイルは「WC分析ツール」という、計量機（アンリツ／イシダ／旧イシダ／
WC計量機）が吐き出すCSV・txtファイルを読み込み、
 1) OK品だけを取り出して統計計算をし、
 2) ヒストグラムと時系列グラフを作り、
 3) 見やすいExcelレポートとして保存する
デスクトップアプリです。全体で約1,300行ありますが、
「絶対に説明できるべき計算部分」「仕組みだけ分かればいい部分」
「ブラックボックスでいい部分」の3段階に分けて読み解きます。


-------------------------------------------------------------------
■ 全体の処理の流れ（まずはここだけ押さえる）
-------------------------------------------------------------------

  1. run() でファイル選択ダイアログを開く（CSVまたはtxt）
       ↓
  2. process_files() が振り分け
       ・txtファイル → process_txt_files()（1ファイル＝1ロット）
       ・CSVファイル → normalize_columns() でメーカー別の形式を統一
                        → LotPreviewDialog でロット分割を確認
                        → process_lot() へ
       ↓
  3. process_lot() が1ロットぶんの本体処理を行う
       ・analyze() で統計値を計算
       ・matplotlibでヒストグラム／時系列グラフを作成
       ・save_to_excel() でExcelファイルに書き出す
       ↓
  4. デスクトップに「分析結果_◯◯.xlsx」として保存、完了メッセージを表示

「ロット」とは、一定時間（デフォルト30分）以上データが途切れたところで
区切った、ひとまとまりの製造単位のことです（LotPreviewDialogでユーザーが
しきい値を選べる）。

【最重要】自分の言葉で説明できるようにすべき部分（合計 約200行）

-------------------------------------------------------------------
■ 1. analyze() 関数（454〜474行目）― 統計計算の核心
-------------------------------------------------------------------

    def analyze(data):
        data = np.asarray(data).astype(float).ravel()
        data = data[~np.isnan(data)]

        n = len(data)
        if n < 2:
            return None, None, (None, None), None, None, None, None

        mean = float(np.mean(data))
        std = float(np.std(data, ddof=1))

        t_value = stats.t.ppf(0.975, df=n - 1)
        margin = t_value * std / np.sqrt(n)

        max1 = float(np.max(data))
        min1 = float(np.min(data))
        lower = mean - 3 * std
        upper = mean + 3 * std

        return mean, std, (mean - margin, mean + margin), max1, min1, lower, upper

やっていることを1行ずつ：

  ・data = np.asarray(...).astype(float).ravel()
      渡された測定値の配列を、1次元のfloat配列に整形する（型がバラバラでも
      計算できるようにする前処理）。

  ・data = data[~np.isnan(data)]
      NaN（数値に変換できなかった欠損値）を除外する。

  ・n = len(data); if n < 2: return None,...
      データが2件未満だと分散が計算できない（標準偏差の定義上、n-1で割るため
      n=1だとゼロ割りになる）ので、計算せずにNoneを返す。
      これがコード内の MIN_OK_COUNT = 2 という定数の根拠になっている。

  ・mean = np.mean(data)
      算術平均（相加平均）。単純にすべて足してnで割った値。

  ・std = np.std(data, ddof=1)
      標準偏差。ddof=1は「不偏標準偏差」を意味し、n-1で割る計算方式
      （標本から母集団のばらつきを推定するときの標準的な式）。
      統計検定2級の「標本標準偏差」に相当。

  ・t_value = stats.t.ppf(0.975, df=n-1)
      t分布の97.5パーセント点。95%信頼区間を作るために、両側2.5%ずつを
      切り捨てた境界値を求めている（両側検定でα=0.05のときの片側0.975）。
      自由度(df)はn-1。サンプル数が少ないときは正規分布ではなくt分布を
      使うのが統計的に正しい（nが大きくなるほど正規分布のZ値1.96に近づく）。

  ・margin = t_value * std / np.sqrt(n)
      母平均の95%信頼区間の「誤差幅」。標準誤差（std/√n）にt値を掛けたもの。
      つまり「本当の平均は、この幅の中に95%の確率で入っているはず」という
      統計的な誤差の見積もり。

  ・max1, min1
      単純な最大値・最小値。

  ・lower = mean - 3*std, upper = mean + 3*std
      いわゆる「3σ管理限界線」。品質管理でよく使う考え方で、正規分布に
      従うデータなら平均±3σの中に約99.7%のデータが収まるはず、という
      経験則に基づく外れ値判定の基準線。この関数自体はこの線を「計算する
      だけ」で、実際に外れ値を弾く判定は process_lot() 側で行っている
      （lower/upperを超えたレコードを outliers_df として抽出している）。

  戻り値: (平均, 標準偏差, (信頼区間下限, 信頼区間上限), 最大値, 最小値,
           -3σ下限, +3σ上限) の7つをタプルで返す。

  ポイント: analyze()自体は「OK品かNG品か」の判定はしない。すでにOK品に
  絞り込まれた測定値の配列を受け取って、統計量を計算するだけの関数。
  外れ値判定・OK/NGの区別は呼び出し元の process_lot() の役割。


-------------------------------------------------------------------
■ 2. normalize_columns() 関数（321〜423行目）― メーカー判定と列統一
-------------------------------------------------------------------

計量機メーカーによってCSVのフォーマットがバラバラなので、この関数が
「読み込んだCSVがどのメーカーの形式か」を推測し、後続処理が扱いやすい
共通の5列（測定値出力No. / 日付時刻 / 測定値(g) / ランクコード / メーカー）
に統一する。判定は上から順に3パターンを試す「早い者勝ち」方式：

  【パターンA: アンリツ】（329〜359行目）
    判定方法: 列名に「測定値」と「ランクコード」という文字列が
              両方含まれているかで判定（ヘッダーが正常に読めるフォーマット）。
    処理: 必要な列だけ抜き出し、型変換（文字列→数値・日付）をして返す。
    品種番号: 「品種」列の先頭の値を hinshoku_num として取得。

  【パターンB: 旧イシダ（WeightLog形式）】（361〜385行目）
    判定方法: この機種はヘッダーが文字化けして読めないため、
              「列の位置」で判定する。8列目（0始まりでインデックス7）が
              1,2,3,16のいずれかの値を95%以上占めているかをチェック。
              これは振分ステータスのコード値（1=OK, 2=軽量, 3=過量, 16=NG）
              に対応しているという業務知識に基づく決め打ちの判定。
    処理: status_map = {1:"2", 2:"1", 3:"E", 16:"N"} で、機種独自のコードを
              アプリ共通のランクコード（"2"=OK, "1"=軽量, "E"=過量, "N"=NG）
              に変換する。

  【パターンC: イシダ】（387〜423行目）
    判定方法: 上の2パターンに当てはまらなかった場合、ファイルの先頭10行を
              スキップして読み直し（イシダ形式はヘッダーの上に説明文が
              10行入っているため）、6列目に「正量」「軽量」「過量」という
              日本語の判定値が含まれているかで判定。
    処理: 同様にrank_map = {"正量":"2", "軽量":"1", "過量":"E"} で変換。
    どれにも当てはまらない場合は ValueError を投げてエラーメッセージを表示。

  共通の後処理:
    ・列名の全角/半角スペースを除去（データ提供元によって表記ゆれがあるため）
    ・重複列を除去
    ・「品種」「予約番号」列などから hinshoku_num（品種番号）を1つ拾う

  つまりこの関数は「if文の連鎖で機種を当てて、それぞれの機種固有ルールで
  列を並べ替える変換器」。統計計算は一切していない、データクレンジングの
  役割のみ。

■ 3. process_lot() 関数（825〜1046行目）― 外れ値判定とOK品の定義
-------------------------------------------------------------------

この関数が「1ロット分のExcelレポートを作る」中心処理。統計・外れ値判定に
関わる部分だけ抜き出すと：

  ・OK品の定義（842行目）
        df_ok = group[group["ランクコード"] == "2"].copy()
    ランクコードが "2" の行だけを「OK品」として扱う。
    _RANK_LABEL_MAP = {"2":"OK", "1":"軽量", "E":"過量", "0":"２個乗り","N":"NG"}
    （29〜33行目の定数）を見ると分かる通り、"2"以外はすべて何らかの
    異常（軽量・過量・二個乗り・NG）を意味するコード。
    つまり統計計算（平均・標準偏差など）はOK品のみを対象に行われ、
    NG品や軽量・過量品は「母集団の分布」には含めない設計。

  ・件数チェック（849〜850行目）
        if len(data) < MIN_OK_COUNT:
            return ("skip", len(data))
    OKデータが2件未満のロットは統計計算できないため、Excelを作らずスキップ
    する（analyze()内のn<2チェックと対応している安全策）。

  ・外れ値の抽出（854行目）
        outliers_df = df_ok[(df_ok["測定値(g)"] < lower) | (df_ok["測定値(g)"] > upper)]
    analyze()が返した3σの上限・下限を使って、OK品の中からさらに
    「統計的に見て外れている値」を抜き出す。これはランクコード上はOK
    （計量機自体はOKと判定した）だが、統計的には異常に見える値、という
    2段階目のチェック。Excel上ではこの外れ値を赤色でハイライトする
    （save_to_excel内の処理）。

  ・不良率の計算（save_to_excel呼び出し前、_create_report_sheet内 514〜515行目）
        ng_count = total_count - original_ok_count
        defect_rate = ng_count / total_count * 100
    「全体件数からOK件数を引いたものがNG件数」「NG件数÷全体件数が不良率」
    という単純な割合計算。

まとめると、このツールの「OK品」の定義は一貫して「計量機が付けたランク
コードが"2"であること」。それとは別に、OK品の中でも平均±3σから外れた
ものを「統計的な外れ値」として別枠で警告する、という2階建ての判定構造に
なっている。


===================================================================
【中程度】仕組みだけ分かっていればいい部分
===================================================================

・Excel出力まわり（_create_report_sheet, save_to_excel, 480〜819行目）
    openpyxlを使って、セルの色・フォント・罫線・列幅を1つずつ指定し、
    「分析レポート」シートに統計値の表・ランク集計・グラフ画像を
    レイアウトしている。matplotlibで作ったグラフはPNG画像として
    BytesIO（メモリ上のバイト列）に保存し、それをExcelのセルに
    画像として貼り付けている（TwoCellAnchorはセル位置を基準に画像の
    表示範囲を固定する仕組み）。行の高さ・列の幅の数値は、印刷時に
    A4用紙にきれいに収まるよう手作業で微調整された値。
    → 「Excelの見た目を作っている部分」という理解で十分。

・グラフ描画（process_lot内 880〜1024行目）
    matplotlibでヒストグラム（fig1）、OK品のみの時系列散布図（fig2）、
    全データ（OK/軽量/過量/NG全部）の時系列散布図（fig3）の3種類を作る。
    色分け（青=OK、赤=過量/NG、オレンジ=軽量）、平均線・3σ線の描画、
    外れ値への注釈（矢印付きラベル）など、見やすくするための細かい
    描画コードが並んでいるだけで、統計的な意味は analyze() の結果を
    そのままグラフ化しているに過ぎない。

・LotPreviewDialog（87〜229行目）
    測定時刻の間隔が指定した分数（10/15/30/45/60分）より空いたら新しい
    ロットとして区切る、というルールをTreeviewの表でプレビューし、
    ユーザーが確認・変更できるようにするダイアログ。
    計算の核はシンプルで、時刻を差分して、しきい値を超えた回数を
    累積カウントすることでロット番号を振っている（160〜164行目の
    _compute_lots）。

・normalize_txt() / convert_txt_to_csv.py
    WC計量機のtxt出力（「No. 値1 値2」のような固定書式のテキスト）を
    正規表現でパースし、値に "*" が付いていればNG、無ければOKとして
    共通フォーマットに変換する。この機種だけは時刻・品種番号・
    軽量/過量の区別が測定データに含まれないため、他メーカーと違い
    ロット分割ダイアログを使わず「1ファイル＝1ロット」として扱う
    （process_txt_files, 1092〜1099行目のコメントに理由が明記されている）。


===================================================================
【ブラックボックスでよい部分】
===================================================================

・_setup_app_style(), _setup_japanese_font()
    Tkinterの見た目（配色・フォント）の設定。「GUIの配色とフォントを
    決めている」で十分。

・ProgressDialog, _run_in_background()（235〜303行目）
    Excel作成やグラフ描画は時間がかかる重い処理なので、これをメインの
    GUIスレッドとは別の裏方スレッド（threading.Thread）で実行し、
    進捗状況だけをqueueという安全な受け渡し役を通じてメイン画面に
    伝えている。「GUIが固まらないように別スレッドで重い処理を動かし、
    進捗バーを更新している」の一言で足りる。Tkinter自体はメインスレッド
    以外からの直接操作が禁止されているための定石パターン。

・_expand_folders(), _read_csv() のエンコーディング判定
    フォルダが選択されたら中のCSV/txtを展開する、CSVの文字コードを
    cp932→utf-8-sigの順に試す、といった細かい実務対応。仕組みの説明が
    できれば十分で、行ごとの理解は不要。
